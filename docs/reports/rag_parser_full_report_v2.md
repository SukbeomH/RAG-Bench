> **문서 버전**: v2.0 | **작성일**: 2026-03-04 | **평가 기준일**: Phase 4 완료
>
> **대상 독자**: 기술 의사결정자 및 경영진 | **평가 방법**: 가중 평점 매트릭스 (Weighted Scoring Matrix)

## 1. Executive Summary

### 왜 지금 결정이 필요한가

RAG(검색 증강 생성) 시스템에서 **문서 파싱 품질은 AI 응답 정확도의 상한선을 결정합니다.** 파싱이 부정확하면 아무리 좋은 검색·생성 모델을 사용해도 정확한 답변을 제공할 수 없습니다. 현재 파싱 솔루션 미선정 상태가 지속되면 RAG 시스템 구축 일정이 지연되며, 임의 선택 시 정확도 최대 56% 격차(최상위 NED 0.76 vs 최하위 0.49)가 발생할 수 있습니다.

### 평가 방법

6종의 PDF 파싱 솔루션을 대상으로, 11개 한국어 PDF(55페이지)에 대해 텍스트 정확도(NED)와 표 구조 정확도(TEDS)를 측정했습니다. 파싱 정확도, 보안, 비용, DPI 안정성 등 6개 기준에 사전 확정된 가중치를 적용하여 종합 점수를 산출했습니다.

### 핵심 발견

- **PaddleOCR-VL**(로컬, 0.9B 파라미터)이 종합 가중 점수 **4.75/5.00**으로 1위를 차지했습니다. 텍스트 정확도(NED 0.7594) 종합 1위, 그래프형 문서에서 2위 대비 +16.7%p 압도적 우위, API 비용 0원, 외부 데이터 전송 없음 등 전 기준에서 고르게 강점을 보였습니다.
- **Upstage API**가 2위(3.60점)로, 텍스트형·표형 문서에서 NED 1위(0.85, 0.81)이며 표 구조(TEDS 0.63)에서 유일하게 0.6을 돌파했습니다. 단, API 비용 발생과 외부 데이터 전송이 제약입니다.
- 1위(PaddleOCR-VL)와 2위(Upstage)의 텍스트형·표형 NED 차이는 2.4~2.7%p로 실질적 동등 구간입니다.

### 추천

**PaddleOCR-VL을 기본 파싱 백엔드로 추천합니다.** 종합 정확도 1위이면서 비용이 0원이고, 문서 데이터가 외부로 전송되지 않아 보안을 완전히 확보합니다. 표 구조 정확도가 최우선인 특수한 경우에 한해 Upstage API를 보조 백엔드로 병행할 것을 제안합니다.

### 다음 단계

1. PaddleOCR-VL K8s 서비스 프로덕션 환경 배포 (GPU 노드 할당 시 처리 속도 대폭 개선 기대)
2. Phase 5 — MinerU Pipeline 백엔드 추가 평가 (예상 NED 0.80+, 순위 변동 가능)
3. Hybrid 라우팅 구현: 텍스트 전용 페이지는 PyMuPDF(2초/페이지), 비주얼 페이지는 PaddleOCR-VL

## 2. 배경 및 범위

### 프로젝트 배경

AutoRAG 프로젝트는 한국어 문서에 대한 검색 증강 생성(RAG) 시스템을 구축합니다. RAG 파이프라인의 첫 단계인 "PDF를 텍스트(Markdown)로 변환"하는 과정에서 어떤 파싱 솔루션을 사용하느냐에 따라 후속 검색·생성의 품질 상한이 결정됩니다.

### 평가 범위

| 항목 | 내용 |
|---|---|
| **평가 대상** | 6종 파싱 솔루션 (로컬 3종 + API 3종) |
| **테스트 문서** | 한국어 PDF 11개, 총 55페이지 |
| **문서 유형** | 텍스트형 1종, 표형 5종(DPI 변형 포함), 그래프형 5종(DPI 변형 포함) |
| **평가 지표** | NED(텍스트 정확도), TEDS(표 구조 정확도) |
| **평가 모드** | Direct — 각 백엔드의 순수 성능 비교 (라우팅 미적용) |

### 핵심 질문

1. 어떤 솔루션이 어떤 문서 유형에 가장 정확한가?
2. 이미지 해상도(DPI) 저하가 정확도에 미치는 영향은?
3. 로컬 솔루션이 유료 API 솔루션을 대체할 수 있는가?

## 3. 평가 방법론

### 측정 지표 설명

| 지표 | 정식 명칭 | 의미 | 범위 |
|---|---|---|---|
| **NED** | Normalized Edit Distance | 변환된 텍스트와 정답(Ground Truth) 간 일치도. 1에 가까울수록 정확 | 0~1 |
| **TEDS** | Tree Edit Distance Similarity | 표의 셀 단위 텍스트 일치도 + 표 개수 일치 패널티. 1에 가까울수록 정확 | 0~1 |

### 평가 절차

1. 11개 PDF에 대해 수작업으로 정답(Ground Truth) Markdown을 작성
2. 6종 솔루션 각각으로 동일 PDF를 변환
3. 변환 결과와 정답을 NED/TEDS로 정량 비교
4. 사전 확정된 6개 기준·가중치로 종합 점수 산출

### 데이터 출처 및 신뢰도

| Docling | K8s 20260227-1118 | 5/11 | [!] 부분 — 라이브러리 호환 문제로 DPI 변형 미실행 |

## 4. 평가 기준 및 가중치

### 가중치 설정 근거

가중치는 벤치마크 실행 **이전에** 확정했으며, RAG 시스템의 비즈니스 요구사항을 반영합니다.

| 기준 | 가중치 | 설정 근거 |
|---|:---:|---|
| **파싱 정확도 (NED)** | 35% | RAG 응답 품질의 상한선을 직접 결정하는 핵심 지표 |
| **데이터 보안** | 20% | 기업 내부 문서가 외부 API로 전송되는 것은 보안 정책상 중대한 리스크 |
| **비용 효율성** | 15% | 대량 문서 처리 시 API 종량제 비용이 급격히 증가 |
| **표 구조 정확도 (TEDS)** | 15% | 재무·법률 문서의 표 데이터 정확성이 업무에 직결 |
| **DPI 안정성** | 10% | 실무 문서의 이미지 품질은 다양하며, 품질 저하에도 안정적이어야 함 |
| **도입 용이성** | 5% | 초기 구축 비용보다 장기 운영 효과가 중요하므로 상대적 저가중 |

### 필수 요건 (Pass/Fail)

아래 요건을 충족하지 못하는 솔루션은 평가에서 제외하지 않되, 리스크 섹션에서 별도 표기합니다.

| 요건 | 설명 |
|---|---|
| 한국어 지원 | 한국어 텍스트를 정상적으로 인식·추출할 수 있어야 함 |
| Markdown 출력 | RAG 파이프라인에 투입 가능한 Markdown 형식으로 출력 |
| 11종 PDF 처리 | 텍스트형, 표형, 그래프형 문서를 모두 처리할 수 있어야 함 |

### 6-3. DPI 안정성 분석

문서를 스캔하거나 이미지로 변환할 때 해상도(DPI, 인치당 점 수)가 달라지면 파싱 정확도에 영향을 줍니다. DPI 변화에도 정확도가 안정적인 솔루션이 실무에서 신뢰할 수 있습니다.

**표형 — DPI별 NED 변화**

| DPI | Upstage | Upstage Enh. | PaddleOCR-VL | OpenAI GPT-4o |
|:---:|:---:|:---:|:---:|:---:|
| 기본 | 0.8080 | 0.7946 | 0.7766 | 0.7010 |
| 72 (저해상도) | 0.7990 | 0.7833 | 0.7745 | 0.6352 |
| 150 | 0.8087 | 0.7820 | 0.7980 | **0.2569** [!!] |
| 200 | 0.8087 | 0.7962 | 0.7762 | 0.6764 |
| **변동폭** | **±1%p** | **±1.3%p** | **±2.4%p** | **±44%p** |

**그래프형 — DPI별 NED 변화**

| DPI | PaddleOCR-VL | Upstage | OpenAI GPT-4o | Upstage Enh. |
|:---:|:---:|:---:|:---:|:---:|
| 기본 | 0.7281 | 0.5329 | 0.5886 | 0.1120 |
| 72 (저해상도) | 0.7096 | 0.5294 | 0.4867 | 0.1011 |
| 150 | 0.7285 | 0.4955 | 0.5696 | 0.1147 |

**분석 요약:**
- **Upstage, PaddleOCR-VL**: 두 솔루션 모두 DPI 변화에 거의 영향받지 않습니다(±1~3%p). 실무에서 다양한 품질의 문서를 처리해도 안정적입니다.
- **OpenAI GPT-4o**: 150dpi 표형에서 NED가 0.26으로 급락하는 이상치가 발생했습니다. DPI에 민감하여 실무 신뢰성이 낮습니다.
- **Upstage Enhanced**: 변동폭 자체는 작지만, 그래프형에서 전 DPI 구간 0.10~0.12로 일관되게 저조합니다.

## 9. 추천

### 기본 추천: PaddleOCR-VL

**PaddleOCR-VL을 RAG 시스템의 기본 PDF 파싱 백엔드로 추천합니다.**

- **정확도 1위**: 종합 NED 0.7594로 6종 중 최고. 그래프형에서 2위 대비 +16.7%p 압도적
- **비용 0원**: 오픈소스(Apache-2.0), 로컬 실행. 문서량 증가에도 추가 비용 없음
- **보안 완전 확보**: 문서 데이터가 외부로 전송되지 않음. 사내 배포 완결
- **DPI 안정성**: 이미지 해상도 변화에 ±2.6%p 이내로 안정적

### 차순위: Upstage (보조 백엔드)

Upstage는 텍스트형 NED 0.8493(1위), 표형 TEDS 0.6316(1위)으로 텍스트·표 정확도에서 최고입니다. **표 구조 정확도가 최우선인 특수한 경우**(재무제표, 법률 서식 등)에 한해 보조 백엔드로 병행할 것을 제안합니다. 단, 외부 API 데이터 전송과 종량제 비용이 수반되므로 민감 문서에는 사용하지 않아야 합니다.

### 미선정 사유 (나머지 4종)

| 솔루션 | 미선정 사유 |
|---|---|
| **OpenAI GPT-4o** | 종합 5위. 가장 느리고(3~5분/페이지) 가장 비싸며, 150dpi 이상치(NED 0.26) 등 안정성 부족 |
| **PyMuPDF** | 이미지 기반 PDF를 전혀 처리할 수 없어 범용 파서로 부적합. Hybrid 라우팅의 텍스트 전용 보조로만 활용 |
| **Docling** | transformers 라이브러리 호환 문제로 로컬 재현 불가. 안정화 후 재평가 대상 |
| **Upstage Enhanced** | 그래프형 NED 0.1118로 기본 Upstage(0.55) 대비 80% 하락. 문서 유형별 성능 편차가 너무 큼 |

### 추천 전제 조건

이 추천은 다음 가정이 유지될 때 유효합니다:

1. **K8s 인프라 가용**: PaddleOCR-VL 서비스 배포를 위한 K8s 노드(8Gi+ 메모리) 확보
2. **Phase 5 결과 미반영**: MinerU Pipeline(예상 NED 0.80+) 추가 시 순위 변동 가능 — Phase 5 완료 후 재평가
3. **GPU 미배정 전제**: 현재 CPU 환경 기준 속도(~1.5분/페이지). GPU 할당 시 속도 대폭 개선 가능
4. **보안 정책 유지**: 외부 API 데이터 전송 제한 정책이 변경되면 Upstage 비중 상향 재검토

## 부록 E. 제약사항

1. **PyMuPDF/Docling 데이터 부분성**: K8s Phase1 결과로 11개 PDF 중 5개만 실행. 이미지 기반 PDF는 PyMuPDF가 처리할 수 없어 `—` 표시
2. **Docling 로컬 재현 불가**: `transformers>=4.49.0` 호환 문제로 로컬 실행이 차단됨. K8s 환경에서만 결과 수집
3. **OpenAI 150dpi 이상치**: `table_image_150dpi`에서 NED 0.2569 기록. 다른 DPI 대비 비정상적 저하이며 원인은 미확인
4. **Upstage Enhanced 그래프형 급락**: 전 DPI 구간에서 NED 0.10~0.12로 일관 저조. 기본 Upstage(0.55) 대비 약 80% 하락
5. **속도 데이터의 환경 의존성**: K8s CPU 환경 기준. GPU 환경에서는 PaddleOCR-VL, Docling 속도가 대폭 개선될 수 있음
6. **Phase 5 미반영**: MinerU Pipeline 백엔드 추가 시 순위 변동 가능 (예상 NED 0.80+, TEDS 0.70+)
7. **파라미터 비공개**: Upstage 계열은 모델 크기 비공개로 효율 비교 불가. OpenAI GPT-4o는 ~200B 추정치 사용
