# 벤치마크 범위 가이드라인

> 작성일: 2026-02-24
> 목적: 서비스 벤치마크 시스템의 평가 범위와 지표 선정 근거 명확화
> 대상: 개발팀, 데이터팀 (벤치마크 설계 판단 기준 공유)

---

## 1. 벤치마크의 핵심 질문

이 벤치마크가 답하려는 질문은 하나다.

> **"문서 종류별로 어떤 Dense × Sparse 임베딩 조합이 가장 높은 검색·답변 품질을 내는가?"**

이 질문에 집중하면 평가 지표와 제외 요소의 경계가 자연스럽게 결정된다.

---

## 2. 벤치마크 조합 범위 (Combination Scope)

### 2-1. 비교 변수 (독립 변수)

| 레이어 | 항목 | 후보 |
|--------|------|------|
| Layer 1 | Dense 임베딩 | kosimcse, e5, bge-m3 (3종) |
| Layer 2 | Sparse 임베딩 | korean_bm25, splade (2종) |

**총 비교 조합: 3 × 2 = 6개**

### 2-2. 고정 변수 (통제 변수)

| 레이어 | 항목 | 고정값 | 근거 |
|--------|------|--------|------|
| Layer 3 | Reranker | ColBERT **항시 적용** | 서비스 파이프라인 필수 구성 요소, 비교 대상 아님 |
| Layer 4 | Contextual Retrieval | **항시 적용** | 서비스 파이프라인 필수 구성 요소, 비교 대상 아님 |

### 2-3. 제외 조합

- **단일 Dense 전용** (Sparse 없음): 허용하지 않음
- **단일 Sparse 전용** (Dense 없음): 허용하지 않음
- **리랭커 미적용** 조합: service 프리셋에서 허용하지 않음
- **Contextual 미적용** 조합: service 프리셋에서 허용하지 않음

모든 조합은 반드시 `Dense + Sparse + ColBERT + Contextual` 4개 레이어를 모두 포함해야 한다.
이 제약은 `ComboSpec.__post_init__`으로 코드 레벨에서 강제된다.

### 2-4. 벤치마크 조합 전체 목록 (6개)

```
kosimcse + korean_bm25 + colbert + contextual
kosimcse + splade      + colbert + contextual
e5       + korean_bm25 + colbert + contextual
e5       + splade      + colbert + contextual
bge-m3   + korean_bm25 + colbert + contextual
bge-m3   + splade      + colbert + contextual
```

## 3. 1차 평가 지표 (Primary Metrics)

RAGAS 기반 품질 지표만을 순위 결정에 사용한다.

| 지표 | 측정 대상 | 가중치 프로파일 |
|------|-----------|-----------------|
| `context_precision` | 검색된 청크의 노이즈 비율 | balanced 0.25 |
| `context_recall` | 필요한 정보의 누락 비율 | balanced 0.25 |
| `faithfulness` | 답변이 컨텍스트에 근거한 정도 | balanced 0.25 |
| `answer_relevancy` | 답변이 질문에 얼마나 적합한가 | balanced 0.25 |

**선정 근거:**
- 검색 지표(`context_*`)는 LLM 품질과 완전히 독립적 — Ollama/OpenAI 여부 무관
- 답변 지표(`faithfulness`, `relevancy`)는 평가자(RAGAS)가 OpenAI 고정이므로 기준 일관성 보장
- 가중치 합산 점수(`weighted_score`)가 전략 최종 순위를 결정

---

## 4. 레이턴시 / 응답 시간 제외 근거

레이턴시는 **1차 평가 지표에서 제외**한다.

### 3-1. 측정 환경 오염 문제

```
전체 파이프라인 응답 시간
= [문서 검색] + [컨텍스트 조합] + [LLM 추론] + [응답 파싱]
         ↑                              ↑
  전략별 차이 발생              모든 조합에 동일한
  (측정하고 싶은 부분)          Ollama 추론 시간이 지배
```

로컬 M2 Pro 환경에서 LLM 추론 시간(qwen3:4b ≈ 2–5초)이 전체 레이턴시의 80% 이상을 차지한다.
임베딩 검색 전략 간 실제 차이(수십 ms 수준)는 이 노이즈에 묻혀 신뢰할 수 있는 비교가 불가능하다.

추가로, 벤치마크는 순차 실행되므로 이전 전략의 모델 캐시 상태, Qdrant 인스턴스 워밍업 여부 등 비재현적 요소가 측정값에 개입한다.

### 3-2. 프로덕션 환경 비전이성

| 항목 | 벤치마크 환경 | 프로덕션 환경 |
|------|--------------|---------------|
| 하드웨어 | M2 Pro (CPU 추론) | GPU 서버 / 클라우드 |
| LLM | Ollama 로컬 | API 또는 서버 추론 |
| 동시 요청 | 단일 | 멀티 스레드 |
| 캐시 상태 | 콜드/워밍업 혼재 | 프리워밍 가능 |

개발 환경에서 측정한 절대적 레이턴시 수치는 프로덕션에서 재현되지 않는다.
레이턴시 기반으로 전략을 탈락시키면, 실제 배포 환경에서 더 빠를 수 있는 전략을 잘못 제거하게 된다.

### 3-3. 벤치마크 목적과 무관

이 벤치마크의 결과물은:

```
"법률 계약서 → kosimcse + bm25 권장 (Context Recall 1위, 이유: 한국어 형태소 강점)"
```

레이턴시는 이 결론을 내리는 데 필요하지 않다.
레이턴시 결정은 다음 단계(서비스 SLA 설계, 인프라 선택)에서 다루어야 한다.

### 3-4. 통제 변수 원칙

ColBERT 리랭킹과 Contextual Retrieval은 **모든 조합에 고정 적용**된다.
순위에 영향을 줄 수 있는 레이턴시 차이는 Dense × Sparse 선택의 차이에서만 발생해야 한다.
만약 레이턴시를 포함하면, 전략 선택이 아닌 실행 환경의 편차가 순위를 왜곡할 수 있다.

## 5. 보조 참고값 (Supplementary Reference)

레이턴시를 완전히 버리지는 않는다. **순위 결정에는 사용하지 않지만** 참고용으로 기록한다.

| 참고값 | 기록 목적 | 활용 시나리오 |
|--------|-----------|---------------|
| 인덱싱 소요 시간 (초) | 전략별 빌드 비용 파악 | Contextual 전처리 오버헤드 확인 |
| 검색 레이턴시 (ms) | 전략 간 상대적 검색 속도 | 1차 지표 동점 시 타이브레이커 |
| LLM 호출 횟수 | API 비용 추정 | OpenAI 기반 전략의 비용 예측 |

이 값들은 `RunTracker`를 통해 자동 기록되며, 보고서의 부록(Appendix) 섹션에 포함된다.

## 6. 레이턴시가 1차 지표가 되어야 하는 예외 상황

다음 조건 중 하나라도 해당되면 별도 레이턴시 벤치마크를 수행한다. (현재 시스템과 분리)

| 예외 조건 | 판단 기준 |
|-----------|-----------|
| 실시간 챗봇 SLA ≤ 500ms 요구 | 제품 요구사항으로 명시된 경우 |
| 1차 지표 점수 차이 < 0.02 | 사실상 동점인 전략 비교 시 |
| 고빈도 쿼리 (> 100 QPS) | 처리량 기반 인프라 선택 필요 시 |

현재 벤치마크는 이 조건에 해당하지 않으므로 레이턴시는 보조 참고값으로 유지한다.

## 7. 요약

```
[질문] "문서 종류별로 어떤 Dense × Sparse 조합이 최선인가?"
         ↓
[비교 변수] Dense 3종 × Sparse 2종 = 6개 조합
            (모든 조합에 ColBERT + Contextual 항시 적용)
         ↓
[1차 지표] context_precision / context_recall / faithfulness / answer_relevancy
         ↓
[제외] 레이턴시 — 측정 환경 오염, 프로덕션 비전이성, 목적과 무관
[제외] 단일 Dense 전용 / 단일 Sparse 전용 / 리랭커 없음 / Contextual 없음 조합
         ↓
[참고값] 인덱싱 시간, 검색 ms — 동점 시 타이브레이커, 비용 참고용
         ↓
[결과] 문서 타입별 전략 순위 + 선정 근거 보고서
```
