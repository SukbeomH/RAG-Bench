# 경영진 보고서 설계 검토 문서

> 작성일: 2026-02-24
> 목적: `reporter_exec.py` 설계 근거 및 기존 `reporter.py`와의 차이점 정리
> 대상 독자: 개발팀, 데이터팀 (설계 판단 근거 공유용)

---

## 1. 핵심 문제 진단

### 1-1. 기존 `reporter.py`의 한계

기존 보고서(`reporter.py`)는 **기술 독자 기준**으로 설계되어 있다.
상급자 보고 관점에서 두 가지 구조적 문제가 존재한다.

| 문제 | 현상 | 영향 |
|------|------|------|
| **근거가 흩어져 있음** | "왜 ColBERT를 고정하는가", "BM25 vs SPLADE 차이는 무엇인가"에 대한 서사 없음. 리서치 근거가 각주 수준으로 처리됨 | 기술 배경 없는 독자는 결론만 보이고 이유를 알 수 없음 |
| **측정→판단→추천 흐름 불명확** | 벤치마크 실행 → RAGAS 점수 → 분석 → 선정이 모듈별로 분리 | 전체 논리 흐름을 파악하려면 코드를 읽어야 함 |

### 1-2. 설계 목표

> "바쁜 상급자가 첫 페이지만 읽어도 의사결정이 가능해야 한다"

---

## 2. 핵심 설계 원칙

### 2-1. 역피라미드 구조 (결론 → 근거 → 상세)

기존 `reporter.py`는 **개요 → 데이터 → 결론** 순서다.
경영진 보고서는 반대로 구성한다:

```
기존 reporter.py            reporter_exec.py
─────────────────           ────────────────────────
Section 1: 평가 개요    →   Executive Summary (결론 먼저)
Section 2: 리더보드     →   Section 1: 배경/비즈니스 질문
Section 3: 카테고리 상세 →  Section 2: 측정 방법
Section 4: 강점/약점    →   Section 3: 종합 결과
Section 5: 동점 그룹    →   Section 4: 카테고리별 상세
Section 6: 최종 가이드  →   Section 5: 최종 선정 가이드
                            부록: 기술 세부사항
```

### 2-2. 수치 표현 방식 변경

| 항목 | 기존 (기술용) | 경영진용 |
|------|-------------|---------|
| 모델 점수 | `0.9093` | `2위 대비 9.5% 우세` |
| 모델 이름 | `` `snowflake-ko_korean_bm25_colbert_contextual` `` | `snowflake-ko + BM25` |
| 카테고리 | `LEGAL` | `법률 (계약서·판례)` |
| 지표명 | `context_recall` | `'놓치지 않는 능력'` |
| 순위 표시 | `rank=1` | `🥇 1위` |

### 2-3. 기술 용어 처리 규칙

모든 기술 용어는 **첫 등장 시 괄호 설명** 병기:

```
Dense 검색(의미 기반) vs Sparse 검색(키워드 기반)
ColBERT 리랭커(최종 답변 후보 재정렬 기술)
Contextual 문맥 강화(검색 전 AI로 문맥을 추가하는 기술)
할루시네이션(AI가 사실이 아닌 내용을 지어내는 현상)
```

### 2-4. 차트 제목은 데이터 해석을 직접 전달

```
기존: "카테고리별 성능 비교"
경영진용: "snowflake-ko는 법률/금융/의료에서, bge-m3는 일반 문서에서 강세"
```

### 2-5. 기술 상세는 부록으로 이동

- 모델 파라미터 수, 임베딩 차원: → 부록 A
- RAGAS 가중치 산정 근거 상세: → 부록 B
- 데이터셋 크기·샘플링 전략: → 부록 C
- 재현 커맨드: → 부록 D
- 전체 점수 테이블: → 부록 E

## 3. 보고서 구조 설계

### 3-1. 전체 목차

```
커버 + 메타 (생성일, 평가 범위)
│
├── Executive Summary  ← 바쁜 상급자가 이 페이지만 읽어도 의사결정 가능
│   ├── 핵심 결론 테이블 (문서 종류 → 추천 모델 → 신뢰도)
│   ├── "한 가지만 선택해야 한다면" (단일 추천)
│   └── 즉시 실행 항목 체크리스트
│
├── Section 1: 무엇을, 왜 테스트했는가
│   ├── 비즈니스 질문
│   ├── AI 검색의 두 가지 방식 (Dense vs Sparse 비유 설명)
│   ├── 고정 파이프라인 (ColBERT/Contextual 고정 이유)
│   └── 테스트 범위 요약
│
├── Section 2: 어떻게 측정했는가
│   ├── 테스트 데이터셋 (카테고리별 출처)
│   └── 평가 지표 4가지 (비기술 설명 + 가중치 이유)
│
├── Section 3: 종합 성능 결과
│   ├── 종합 순위표 (1위는 굵게 + 🥇 마커)
│   └── 핵심 인사이트 3가지 (자동 도출)
│
├── Section 4: 문서 종류별 상세 분석
│   └── 카테고리별 동일 템플릿:
│       ├── 문서 특성 + 테스트 데이터
│       ├── 순위 테이블 (1위 대비 %p 차이 포함)
│       └── "왜 이 모델이 1위인가?" — 비기술 설명
│
├── Section 5: 최종 모델 선정 가이드
│   ├── 사용 상황별 추천 테이블
│   ├── 단일 모델 필요 시 추천
│   ├── 동점 구간 처리 (비용·속도 기준 선택 안내)
│   └── API 모델 제외 이유 (보안·비용)
│
└── 부록 (기술 세부사항)
    ├── A. 모델 스펙
    ├── B. 가중치 산정 근거
    ├── C. 데이터셋 상세
    ├── D. 재현 방법
    └── E. 전체 점수 테이블
```

### 3-2. Executive Summary 상세 설계

상급자가 보고서를 받았을 때 **첫 페이지에서 다음 3가지를 즉시 파악**할 수 있어야 한다:

1. **무엇을 추천하는가** — 문서 종류별 추천 모델표
2. **단 하나만 써야 한다면** — 범용 단일 추천
3. **지금 당장 무엇을 해야 하는가** — 즉시 실행 체크리스트

```markdown
| 문서 종류            | 추천 AI 모델 조합        | 신뢰도 | 비고 |
|---------------------|----------------------|--------|------|
| 법률 (계약서·판례)   | **snowflake-ko + BM25** | ★★★   |      |
| 금융·비즈니스        | **snowflake-ko + BM25** | ★★★   |      |
| 의료 (FAQ·공중보건)  | **snowflake-ko + BM25** | ★★★   |      |
| 일반 (백과사전·위키) | **BGE-M3 + SPLADE**     | ★★★   |      |
| 기술 (API·매뉴얼)   | 추가 테스트 필요          | ★☆☆   | 고객 문서 확보 후 재측정 |
```

### 3-3. 카테고리별 상세 분석 — 동일 템플릿

각 카테고리를 동일한 구조로 반복하여 **비교 가독성**을 확보한다:

```
문서 특성: [한 문장 설명]
테스트 데이터: [출처 + 규모]
평가 질의 수: N개

순위별 결과 테이블:
  | 🥇 1위 | 모델명 | 점수 | 기준 (1위) | ... |
  | 🥈 2위 | 모델명 | 점수 | −X.X%p    | ... |
  | 3위    | 모델명 | 점수 | −Y.Y%p    | ... |

왜 [1위 모델]이 [카테고리] 분야에서 1위인가?
  > [비기술 언어로 선정 이유 서술]
```

## 4. 자동 인사이트 도출 로직

`reporter_exec.py`는 데이터에서 핵심 인사이트 3개를 자동 도출한다:

| 인사이트 | 도출 로직 |
|---------|---------|
| **1위 모델의 강점/약점 프로파일** | `insight.py`의 strengths/weaknesses 활용 |
| **복수 카테고리 우세 여부** | 카테고리별 1위 모델 집계 → 2개 이상 우세 시 해당 서술 |
| **동점 구간 존재 여부** | 1위-2위 점수 차 < 3% 카테고리를 감지, 비용 기준 선택 안내 |

## 5. `_format_model_name()` 변환 규칙

기술적인 모델 키를 독자 친화적 표현으로 변환한다.

```python
# 입력: "snowflake-ko_korean_bm25_colbert_contextual"
# 출력: "snowflake-ko + BM25"

Dense 매핑:
  kosimcse     → KoSimCSE
  e5           → E5-multilingual
  bge-m3       → BGE-M3
  snowflake-ko → snowflake-ko
  openai-large → OpenAI (API)
  upstage      → Upstage Solar (API)

Sparse 매핑:
  korean_bm25  → BM25
  splade       → SPLADE
```

리랭커(`colbert`, `flashrank`)와 LLM 지원(`contextual`) 레이블은 조합명에서 **제거**한다.
이들은 고정 파이프라인이므로 조합 비교 이름에 포함할 이유가 없다.

## 6. 신뢰도(★) 산정 기준

| 신뢰도 | 조건 |
|--------|------|
| ★★★ | 표준 공개 데이터셋 사용, 쿼리 수 충분 (≥30) |
| ★★☆ | 데이터셋 규모 소형 또는 쿼리 수 부족 (<30) |
| ★☆☆ | 표준 데이터셋 없음 (TECHNICAL) 또는 데이터 매우 부족 |

현재 하드코딩되어 있으며, 향후 `n_qa` 값 기반 자동 계산으로 개선 가능.

## 7. `reporter.py` vs `reporter_exec.py` 비교

| 항목 | `reporter.py` | `reporter_exec.py` |
|------|-------------|------------------|
| **대상 독자** | 개발자·데이터과학자 | 경영진·비기술 상급자 |
| **보고서 구조** | 평가 개요 → 리더보드 → 결론 | 결론 → 배경 → 측정 → 결과 |
| **수치 표현** | 절대값 (0.9093) | 상대 비교 (2위 대비 9.5%) |
| **모델 이름** | 전체 키 그대로 | 독자 친화 이름 변환 |
| **지표 설명** | 수식/약어 (RAGAS, NDCG) | 비유/쉬운 말 |
| **기술 세부사항** | 본문 포함 | 부록으로 분리 |
| **출력 파일** | `selection_report.md` | `selection_report_exec.md` |
| **인사이트 도출** | 없음 (데이터만 나열) | 3개 핵심 인사이트 자동 서술 |
| **API 제외 설명** | 없음 | 보안·비용 이유 명시 |

두 파일은 **동일한 데이터 파이프라인** (`ranker`, `insight`, `deduplication`, `selector`)을 공유하며,
렌더링 레이어(`_render_*` 함수들)만 분리된다.

## 8. 향후 개선 사항

| 개선 항목 | 우선순위 | 설명 |
|---------|---------|------|
| 신뢰도 자동 계산 | 중 | n_qa 기반으로 ★ 자동 산정 |
| 비기술 선정 이유 자동 생성 | 높 | 현재 도메인별 하드코딩 → LLM으로 자동 생성 |
| HTML 버전 | 낮 | 인터랙티브 차트 포함 경영진 대시보드 |
| 변화 추이 | 낮 | 이전 실행 대비 순위 변동 (↑↓) 표시 |

## 9. 파일 위치

```
rag_bench/analysis/
├── reporter.py          # 기존 — 기술 독자용 (6섹션)
├── reporter_exec.py     # 신규 — 경영진용 (역피라미드 + 부록)
└── ...
```

CLI 실행:
```bash
# 기술용
python -m rag_bench.analysis.reporter --run_dir _benchdata/service_run

# 경영진용
python -m rag_bench.analysis.reporter_exec --run_dir _benchdata/service_run
```

두 보고서를 동시에 생성하려면:
```bash
python -m rag_bench.analysis.reporter --run_dir _benchdata/service_run
python -m rag_bench.analysis.reporter_exec --run_dir _benchdata/service_run
```
